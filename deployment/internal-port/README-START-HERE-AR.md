# حزمة التحويل الداخلي — متابعة المحتوى المحلي

الهدف هو نقل النظام من الواجهة الثابتة المرتبطة بـ Supabase إلى Windows Server + IIS + ASP.NET Core + Microsoft SQL Server داخل شبكة الهيئة.

الحالة: تأسيس تقني غير جاهز للإنتاج. تم الجرد من GitHub وSupabase الحي. توجد 15 جدولًا عامًا ونحو 51 migration مسجلة، بينما المجلد الموجود بالمستودع لا يحتوي جميع migrations الحية. الواجهة الحالية ما زالت تحمل Supabase JS وتتصل بـ Supabase مباشرة.

ملفات المصدر الحالية: `public/` في جذر المستودع. يجب نسخها إلى حزمة التسليم من GitHub، ثم تحويل كل طلبات Supabase إلى API داخلي. لا تستخدم GitHub Pages في التشغيل الداخلي.

لا تتضمن هذه الحزمة بيانات إنتاج أو كلمات مرور أو مفاتيح. تصدير البيانات وStorage objects يجب أن يتم عبر تصدير رسمي مشفر ومنفصل عن المستودع العام.

ترتيب العمل: تثبيت SQL Server version المعتمد؛ تحويل schema وقيودها وviews وfunctions وtriggers وRLS؛ بناء API يغطي كل العمليات؛ تحويل الواجهة؛ نقل البيانات والمرفقات؛ اختبار تكافؤ المؤشرات والصلاحيات؛ ثم تشغيل تجريبي متوازٍ واعتماد الأعمال.
