## الهدف

تجهيز نسخة داخلية لقسم تقنية المعلومات تشمل الموقع، وخلفية API، وقاعدة Microsoft SQL Server، والبيانات الحالية، والمرفقات، وتعليمات التثبيت. لا يتطلب ذلك من صاحب المنصة الدخول إلى خادم الهيئة.

## مكونات المصدر التي يجب نقلها

- 15 جدولًا عامًا، مع المفاتيح الأساسية والخارجية والقيود والفهارس.
- 49 migration مسجلة في قاعدة المصدر حتى وقت الجرد.
- Edge Functions: `icv-new-app` (الإصدار 4) و`manage-platform-user` (الإصدار 9).
- سياسات الوصول والصلاحيات والأدوار، بما فيها: admin وsection_head وeditor وviewer وtemporary_viewer.
- ملفات المرفقات المشار إليها في `project_plan_documents`؛ سجلّا المرفقات لا يعنيان أن بايتات الملفات قد نُقلت.
- إعدادات المنصة، وسجل التدقيق، وتعيينات المستخدمين.

## عناصر لم تكتمل بعد — لا تعتبر هذه الحزمة إصدار تشغيل

1. تحويل PostgreSQL schema والوظائف والمشغلات والسياسات إلى SQL Server وASP.NET Core.
2. بناء طبقة API بديلة لكل استدعاءات Supabase في الواجهة.
3. تصدير البيانات الفعلية في ملف منفصل آمن ثم تحويلها واستيرادها مع التحقق من أعداد السجلات والعلاقات.
4. تنزيل بايتات المرفقات والتحقق من سلامتها وربطها بمسارات التخزين الداخلي.
5. تهيئة حسابات الدخول على النظام الجديد. لا تُنقل كلمات المرور أو مفاتيح الخدمة أو الأسرار إلى المستودع.
6. اختبارات مقارنة الحسابات والتقارير والصلاحيات وسجل التدقيق قبل اعتماد التشغيل.

## حماية البيانات

المستودع مرتبط بموقع GitHub Pages عام؛ لذلك **يُمنع وضع نسخ قاعدة البيانات أو ملفات المرفقات أو بيانات المستخدمين أو الأسرار في هذا المستودع**. توضع ملفات البيانات النهائية في وسيط تسليم مشفر أو قناة داخلية تعتمدها الهيئة، منفصلة عن ملفات الشيفرة.

## قرار تقني مطلوب من تقنية المعلومات

قبل تثبيت SQL Server scripts النهائية، يلزم تأكيد إصدار SQL Server ورقم البناء ومستوى التوافق، واسم الـ Instance، وإصدار Windows Server ونسخة .NET Hosting Bundle المعتمدة. لا يلزم إرسال كلمات مرور أو أسرار عبر المحادثة.

## معيار إعلان الجاهزية

لا توصف الحزمة بأنها جاهزة للتشغيل إلا بعد نجاح:
- إنشاء قاعدة البيانات من الصفر.
- استيراد جميع البيانات مع مطابقة العدد لكل جدول.
- التحقق من المفاتيح والعلاقات وعدم وجود سجلات يتيمة.
- التحقق من تنزيل وفتح كل مرفق.
- تسجيل الدخول واختبار كل دور وصلاحية.
- مقارنة نتائج مؤشرات المحتوى المحلي والتقارير بين النسختين.
- تشغيل نسخة تجريبية داخل الشبكة دون أي اتصال تشغيلي بـ Supabase أو GitHub Pages.
